# Contributing to Brío

Thanks for wanting to help. Most useful first, easiest first:

1. **Report a problem** with the [issue template](../../issues/new/choose). The more exact, the better.
2. **Suggest an improvement** in an issue before coding it, so you don't waste time.
3. **Send a pull request.** Issues labeled `good first issue` are a good starting point.

## Try your changes

Open `Brio.bat` (or `Brio.ps1` with PowerShell as administrator).

## Before sending the PR

- One change per PR, small, with a title that says what it does.
- Every new option must explain what it does, what you gain and what you lose, and must be reversible.
- If it changes something the user sees, add it to `CHANGELOG.md`.
- English or Spanish are both fine in issues and PRs.

Questions? Open an issue and we'll talk it through.

## 🇪🇸 Español

Gracias por querer ayudar. Lo más útil, de más fácil a más difícil:

1. **Contar un problema** con la plantilla de issues. Cuanto más exacto, mejor.
2. **Proponer una mejora** en un issue antes de programarla.
3. **Mandar un Pull Request.** Los issues con la etiqueta `good first issue` son un buen punto de partida.

**Probar tus cambios:** Abrí `Brio.bat` (o `Brio.ps1` con PowerShell como administrador).

**Antes de mandar el PR:** un cambio por PR, chico y con un título claro. Cada opción nueva tiene que explicar qué hace, qué ganás y qué perdés, y tiene que poder revertirse. Si cambia algo que el usuario ve, sumalo a `CHANGELOG.md`. En issues y PRs podés escribir en español o en inglés.
